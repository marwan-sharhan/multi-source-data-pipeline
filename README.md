# مشروع خط أنابيب هندسة بيانات التجارة الإلكترونية متعدد المصادر

## نظرة عامة على المشروع

هذا المشروع عبارة عن تطبيق عملي لخط أنابيب هندسة بيانات (Data Engineering Pipeline)
يقوم بجمع البيانات من عدة مصادر مختلفة، وتخزين البيانات الخام، ثم معالجتها
والتحقق من جودتها، وأخيرًا تحميل البيانات المعالجة إلى قاعدة بيانات SQLite.

يعتمد المشروع على منهجية ETL:

**استخراج → تحويل → تحقق → تحميل**

---

## أهداف المشروع

يهدف المشروع إلى تطبيق المفاهيم الأساسية لهندسة البيانات عمليًا، وتشمل:

- استخراج البيانات من مصادر متعددة.
- الاحتفاظ بنسخة من البيانات الخام قبل المعالجة.
- تحويل وتنظيف البيانات.
- التحقق من جودة البيانات.
- تخزين البيانات المعالجة في قاعدة بيانات SQLite.
- إجراء تحليلات باستخدام SQL.
- إنشاء Dataset جاهز للاستخدام في Machine Learning.
- إنشاء تقرير لجودة البيانات.
- تسجيل عمليات التشغيل باستخدام Logging.
- إجراء اختبارات آلية باستخدام Pytest.
- تنظيم المشروع باستخدام Git.

---

## مصادر البيانات

يستخدم المشروع خمسة أنواع مختلفة من مصادر البيانات:

1. ملفات CSV
2. قاعدة بيانات PostgreSQL
3. REST API
4. Web Scraping
5. قاعدة بيانات MongoDB

### تفاصيل المصادر

- **CSV:** بيانات معاملات التجارة الإلكترونية.
- **PostgreSQL:** بيانات المنتجات.
- **REST API:** بيانات المنتجات من API.
- **Web Scraping:** بيانات الكتب من موقع ويب.
- **MongoDB:** بيانات تقييمات المنتجات.

## مراحل خط أنابيب البيانات

يمر تدفق البيانات بالمراحل التالية:

```text
CSV
PostgreSQL
REST API
Web Scraping
MongoDB
    ↓
الاستخراج (Extract)
    ↓
تخزين البيانات الخام (Raw Storage)
    ↓
المعالجة والتحويل (Transform)
    ↓
التحقق من الجودة (Validate)
    ↓
التحميل (Load)
    ↓
SQLite
    ↓
التحليلات (Analytics)
    ↓
ML-Ready Dataset
```

## استخراج البيانات

يتم استخراج البيانات من خمسة مصادر مختلفة باستخدام أدوات وتقنيات
مناسبة لكل مصدر.

### 1. CSV

يتم استخدام بيانات معاملات التجارة الإلكترونية كمصدر رئيسي للبيانات.

يتم الاحتفاظ بالبيانات الخام في:

```text
data/raw/csv/
```

### 2. PostgreSQL

يتم استخراج بيانات المنتجات من قاعدة بيانات PostgreSQL.

يتم تخزين البيانات الخام في:

```text
data/raw/postgres/
```

### 3. REST API

يتم استخراج بيانات المنتجات من REST API وتخزين الاستجابة الخام
قبل إجراء أي عمليات معالجة.

```text
data/raw/api/
```

### 4. Web Scraping

يتم استخراج بيانات الكتب باستخدام Web Scraping.

يتم حفظ البيانات الخام في:

```text
data/raw/web/
```

### 5. MongoDB

يتم استخراج تقييمات المنتجات من MongoDB.

يتم حفظ البيانات الخام في:

```text
data/raw/mongodb/
```

## معالجة وتحويل البيانات

بعد استخراج البيانات وتخزينها في Raw Storage، يتم تحويل البيانات
بحسب طبيعة كل مصدر.

تشمل عمليات التحويل:

- تنظيف البيانات.
- تحويل أنواع البيانات.
- معالجة القيم غير الصالحة.
- تصنيف المعاملات.
- توحيد بعض الحقول.
- تجهيز البيانات للتحميل إلى قاعدة البيانات.

كما يتم عزل بعض البيانات غير الصالحة في:

```text
data/quarantine/
```

بدلًا من إدخالها مباشرة إلى البيانات النهائية.

## قاعدة البيانات النهائية

بعد معالجة البيانات والتحقق من جودتها، يتم تحميل البيانات إلى قاعدة

الجداول الخاصة بالمصادر الخارجية.

ومن الجداول الموجودة:

```text
customers
products
orders
order_items
reviews
postgres_products
api_products
web_books
```

## تكامل البيانات

تم إجراء مجموعة من عمليات التحقق من العلاقات بين الجداول.

تشمل هذه العمليات:

- التأكد من أن كل `order_item` مرتبط بطلب موجود.
- التأكد من أن كل `order_item` مرتبط بمنتج موجود.
- التأكد من صحة العلاقة بين الطلبات والعملاء.
- التحقق من صحة تقييمات المنتجات.

## التحليلات

تم استخدام SQL لإجراء تحليلات على البيانات المعالجة.

ومن أهم المؤشرات التي تم حسابها:

- إجمالي المبيعات.
- إجمالي قيمة الإلغاءات.
- صافي المبيعات.

وكانت النتائج:

```text
إجمالي المبيعات: 10,642,110.80
قيمة الإلغاءات: -893,979.73
صافي المبيعات: 9,748,131.07
```

## التحقق من جودة البيانات

يتضمن المشروع مجموعة من قواعد التحقق من جودة البيانات، منها:

- التحقق من وجود طلبات بدون عناصر.
- التحقق من وجود عناصر بدون طلبات.
- التحقق من وجود عناصر بدون منتجات.
- التحقق من صحة تقييمات المنتجات.

نتيجة آخر عملية تحقق:

```text
orders_without_items: 0
order_items_without_order: 0
order_items_without_product: 0
invalid_ratings: 0
```

وحالة جميع الاختبارات:

```text
PASS
```

وهذا يعني أن جميع قواعد التحقق الحالية اجتازت الاختبار بنجاح.

## تقرير جودة البيانات

يتم إنشاء تقرير جودة البيانات في:

```text
reports/quality_report.csv
```

ويحتوي التقرير على:

- اسم قاعدة التحقق.
- عدد الصفوف غير الصالحة.
- حالة قاعدة التحقق.

مثال على نتيجة التقرير:

```text
rule,status
orders_without_items,PASS
order_items_without_order,PASS
order_items_without_product,PASS
invalid_ratings,PASS
```

## مجموعة البيانات الجاهزة لـ Machine Learning

تم إنشاء مجموعة بيانات على مستوى العملاء:

```text
data/processed/ml_customers.csv
```

وتحتوي مجموعة البيانات على الخصائص التالية:

- `customer_id`
- `number_of_orders`
- `total_items`
- `total_spent`
- `average_order_value`

تم أيضًا فحص جودة البيانات الناتجة.

وكانت النتائج:

```text
Negative total_items: 0
Negative total_spent: 0
Zero total_items: 0
```

وهذا يعني عدم وجود قيم سالبة أو قيم صفرية في هذه الحقول في مجموعة
البيانات النهائية.

## الخلاصة

يقدم هذا المشروع تطبيقًا عمليًا لمراحل بناء Data Engineering Pipeline
متعدد المصادر.

يبدأ المشروع باستخراج البيانات من خمسة مصادر مختلفة، ثم تخزين البيانات
الخام، ومعالجتها وتحويلها، والتحقق من جودتها، وتحميل البيانات النهائية
إلى SQLite.

بعد ذلك يتم إجراء التحليلات وإنشاء Dataset جاهز للاستخدام في
Machine Learning، بالإضافة إلى إنشاء تقارير جودة البيانات واختبارات
آلية وتسجيل عمليات التشغيل.

وبذلك يغطي المشروع المراحل الأساسية المطلوبة في بناء خط أنابيب بيانات
متكامل ومتعدد المصادر.
